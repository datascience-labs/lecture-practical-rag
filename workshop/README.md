# Practical RAG 01–12: 8시간 가이드 실습 운영안

전공 지식은 있지만 코드를 처음부터 작성하기 어려운 학습자를 위한 과정이다. 목표는 전체 Python 구현을 완성하는 것이 아니라, **RAG의 각 단계가 하는 일을 이해하고, 실패 원인을 찾아 설정을 선택하며, 근거를 확인하는 것**이다.

이 폴더에는 운영 설계, [문항 원본](questions.json), [실행 가능한 실습 웹사이트](site/README.md)가 있다. 웹사이트는 12회차 실습, 24문항 자동 채점, 순차 잠금 해제, 같은 브라우저의 진도 복원, 결과 파일 가져오기·내려받기, 종합 실습 작성을 제공한다. 중앙 학습관리 서버와 실시간 강사 대시보드는 후속 확장 요건이다.

배포된 사이트: **[Practical RAG · 단계별 실습](https://practical-rag-step-lab.sejinchun.chatgpt.site)**. 현재 소유자 전용이며 학생 접근은 별도 공유 설정이 필요하다.

저장소 루트에서 `python3 -m http.server 8765 --directory workshop/site/dist`를 실행한 뒤 `http://localhost:8765`를 연다. 문항·원문을 변경했다면 먼저 `python3 workshop/site/build.py`로 정적 데이터를 다시 생성한다.

## 학습자가 경험할 흐름

```text
시작 안내 → 01 [설명 → 조작 → 관찰 문제 → 코드 빈칸] → 02 → … → 12 → 종합 실습 → 제출
                         ↑ 오답 → 힌트 → 수정·재시도 ↓
```

각 회차는 아래 형식을 반복한다. 기본 설명 20%, 강사와 함께 하는 조작 25%, 개인 실습·문항 40%, 해설·질문 15%를 기준으로 시간을 배분한다. 20분 회차라면 대략 4/5/8/3분이다.

1. **목표·설명:** 이번 단계가 전체 RAG에서 어디에 해당하는지 보여준다. 원본 슬라이드 전체를 재생하지 않고 목표와 핵심 도식·예제만 사용한다.
2. **따라 하기:** 한 화면에 한 가지 행동만 지시한다. 예: `질문 선택 → 후보 수 3 → 실행 → 정답 문서 표시`.
3. **관찰 문제:** 방금 출력한 결과에 관한 객관식 1문항. 단순 용어 암기보다 근거·누락·실패 원인을 묻는다.
4. **핵심 코드:** 완성된 5–10줄 내외 코드에서 토큰 또는 한 식만 입력한다. import·설정·반복문 전체를 작성하게 하지 않는다. 입력 부담이 큰 학습자를 위해 동일한 식을 고르는 코드 카드도 제공한다.
5. **완료:** 조작 결과가 저장되고 두 문항이 모두 통과하면 다음 회차를 연다. 이전 회차는 다시 볼 수 있다.

`questions.json`에는 회차별 목표, 실습 행동, 확인할 결과, 출처, 객관식과 코드 문항, 정답, 힌트, 해설이 있다. 문항은 24개이며, 코드 문항도 문법 전체를 외우게 하지 않고 바로 위 예제를 참고해 해결하도록 한다.

### 완료 조건과 학습 정체 처리

- `locked → available → in_progress → passed` 상태를 사용한다. 첫 회차만 처음에 열린다.
- 실습 실행 기록 + 객관식 정답 + 코드 빈칸 정답을 모두 충족해야 `passed`가 된다. 빈 입력·단순 페이지 방문·실행 버튼 클릭만으로 통과시키지 않는다.
- 실행 기록에는 입력 질문, 설정, 사용 데이터 버전, 출력 또는 출력 ID를 남긴다. 객관식은 실행 결과와 연결한다.
- 오답 횟수에 제한을 두지 않는다. 첫 오답은 관련 개념, 두 번째는 확인할 출력 위치, 세 번째는 풀이 예시를 제공한다. 예시를 본 경우 `assisted`로 기록하고 **다른 동형 문항**으로 다시 확인한다.
- 조교 도움은 `assisted`로 남긴다. 실제 장애 시 강사 예외 해제는 사유와 함께 `waived`로 기록하고, 정상 통과와 구분한다. 이후 보충 실습 대상으로 남긴다.
- 앞선 회차를 복습해도 다음 회차의 통과 상태를 지우지 않는다. 데이터 버전이 바뀌면 영향받는 평가 결과를 별도로 표시한다.
- 이 수업의 수료는 학습용 실습 완료다. 힌트 사용·재시도 횟수를 감점에 쓰지 않는다. 코드 카드 선택과 직접 입력은 같은 학습 목표를 확인한다.

### 종합 실습 40분

새 질문은 회차별 예제를 그대로 반복하지 않는다. 아래 질문은 기존 데이터로 근거를 검수할 수 있다.

| 질문 | 선택할 출발 경로 | 검수할 근거 | 통과 기준 |
|---|---|---|---|
| PD-3000의 최대 출력과 무게는? | 기본 RAG 또는 하이브리드 | `05-product-pd3000.txt` | 650W·2.1kg을 근거와 연결 |
| 대한중공업에 납품하는 제품은 어느 공장에서 생산되나? | Local/그래프 확장 또는 다중 문서 검색 | `08-customers.txt`, `04-product-pd2000.txt`, `07-factories.txt` | 대한중공업 → PD-2000 → 제조1공장(천안)의 관계와 출처 확인 |
| 제품 전환과 ESS 사업을 함께 보면 회사의 사업 방향은? | Global을 후보로 비교 | `01-company-overview.txt`, `04-product-pd2000.txt`, `05-product-pd3000.txt`, `06-product-ess500.txt`, `09-project-atlas.txt` | 세 사업 축을 누락하지 않고 PD-3000·ESS 전환 방향을 근거로 설명 |

강사 시연 5분 → 개인 비교 20분 → 서로 근거 확인 10분 → 제출 5분. 경로 이름만 맞히면 통과시키지 않는다. 다른 경로로도 충분한 근거를 얻었다면 정답으로 인정한다. GraphRAG가 항상 우수하다는 결론을 강제하지 않는다.

최종 제출물은 질문 3개 각각에 대해 `선택 경로 / 확인한 출처 / 답변 / 실패 또는 제한 / 비교 후 선택 이유`다. 최소 한 질문에는 결과가 기대와 달랐을 때 검색 단계와 생성 단계 중 어디를 점검할지 기록한다.

## 웹사이트 구현 요건

### 학습자 화면

- 왼쪽: 01–12 진행 지도와 현재 위치. 잠긴 회차·진행 중·완료·도움받음 상태를 문자로도 표시한다.
- 가운데: 목표, 짧은 개념 설명, 번호가 있는 따라 하기, 실행 결과, 문항. 문제의 답을 찾아야 하는 화면을 닫고 다른 화면으로 이동하게 하지 않는다.
- 오른쪽 또는 펼침 영역: 원문·출처, 용어 도움말, 핵심 코드. 모바일에서는 세로로 배치한다.
- 하단: 힌트, 답 확인, 통과 후 다음 단계. 정답 제출 직후 무엇을 맞혔고 왜 그런지 설명한다.
- 새로고침·연결 중단 후 재개, 키보드 조작, 충분한 글자 크기, 색상 외 상태 표시를 지원한다.
- 개인 결과 내려받기: 회차별 설정·관찰 결과·응답·통과 여부·도움 여부를 포함한다.

### 실행 방식: 기본 경로와 선택 확장

**기본 경로:** 학생 PC에는 브라우저만 필요하게 한다. 임베딩·리랭킹·그래프 추출·리포트 생성 결과는 수업 전에 준비한다. 학습자는 사전 준비된 질문과 설정 조합을 조작하며 결과를 비교한다. 이 경우 화면에 **“준비된 예제 결과”**라고 표시하고 실제 즉석 추론과 구분한다. 출력이 없는 설정 조합은 지원 범위 밖이라고 알린다. 임의 숫자를 만들어 실측 성능처럼 표시하지 않는다.

RRF·Hit@k·MRR·단순 그래프 탐색은 브라우저에서 실제 계산할 수 있다. 이 출력에는 **“브라우저에서 계산”**이라고 표시한다. 청킹은 지정한 규칙에 따라 실제 분할하되, 그 결과에 대한 검색 평가는 미리 계산한 설정에만 연결한다.

**선택 확장:** 강사 서버에서 기존 Python 파이프라인을 실행하면 자유 질문을 허용할 수 있다. API 키는 서버에만 둔다. 임베딩·리랭커는 미리 로딩하고 동시 요청·타임아웃·캐시를 관리한다. 수업 중 학생별 모델 설치와 API 가입은 필수에서 제외한다. 긴 그래프 인덱싱을 수업 시간에 다시 실행하지 않는다.

코드 빈칸은 제출값을 제한된 정답 목록과 비교한다. 공백과 식 전체를 감싼 괄호를 무시하고, 회차 06·09의 `1`/`1.0` 등은 검수한 허용 목록으로 처리한다. 분모의 괄호를 없애 의미가 달라진 식은 거부한다. 학생 입력을 `eval`/`exec`로 실행하지 않는다. 나중에 자유 코딩을 도입한다면 별도 실행 격리를 설계한다.

### 진도 저장과 강사 화면

단일 기기 시제품은 localStorage로 시작할 수 있다. 이 방식은 **같은 브라우저에서만** 재개되며, 기기 변경·중앙 진도 집계·강제적인 통과 제어는 제공하지 않는다. 정답을 클라이언트에서 읽거나 진도를 수정할 수 있으므로 평가 보안이 필요한 시험에 사용하지 않는다.

실제 집합 교육에서는 수업 코드와 임의 학습자 ID를 발급하고 서버에 아래 항목을 저장한다. 이름·이메일을 수업 진행에 불필요하게 요구하지 않는다.

```text
course_version, cohort_id, learner_id, chapter_id, task_id,
run_id, input_config, output_ref, response, attempts,
status(passed/assisted/waived), updated_at
```

서버는 선행 회차 통과 여부와 `run_id`를 검증하고 채점한다. 교사용 화면은 회차별 완료 인원, 정체 인원, 반복 오답, 도움 요청을 보여준다. 학습자 화면과 강사 권한을 구분한다. 원본 `questions.json`은 정답이 포함된 강사용 자료이므로 서버 채점 방식에서는 학생용 API에 정답 필드를 포함하지 않는다.

## 강사·조교 운영

### 수업 전

1. 참가 인원·브라우저·접속망을 확인하고, 수업 코드와 재접속 안내를 배포한다.
2. 원문 버전과 질문 목록을 고정한다. `data/sample_handbook.md`, `data/company_docs/`, `data/eval_set.json`, `data/eval_set_graph.json`을 기준으로 출력·정답·출처를 대조한다.
3. 필수 경로의 모든 질문·설정에 대한 결과를 준비한다. 강사가 처음부터 종합 실습 제출까지 직접 통과해본다.
4. 수업에서 쓸 실제 지연시간·평가 수치가 필요하면 모델·장비·평가셋·설정과 함께 측정한다. 슬라이드의 설명용 수치를 실측치로 복사하지 않는다.
5. 예상 동시 접속 수로 저장·채점·진도 화면을 점검한다. 서버 실행 확장은 동시 추론도 별도로 점검한다.
6. 접속 불가에 대비해 원문 발췌, 결과 표, 문항, 제출 양식의 오프라인 사본을 준비한다.

### 수업 중

- 회차 시작에 강사가 이번 단계의 결과물을 먼저 보여준다. 이후 모두 같은 화면에서 따라 한다.
- 회차 종료 약 5분 전에 진도를 확인한다. 반복 오답은 전체 설명으로, 기기·접속 문제는 조교의 개별 지원으로 처리한다.
- 먼저 끝낸 학습자는 추가 질문 1개를 검토한다. 전체를 기다리는 동안 다음 필수 회차를 선행하도록 강제하지 않는다.
- 뒤처진 학습자에게 답만 대신 입력하지 않는다. 근거 위치를 함께 확인하고 짧은 대체 문제로 이해를 확인한다.
- 네트워크 장애 시 동일한 결과 표와 문항으로 진행하고, 장애 완료 기록은 복구 후 별도로 반영한다.

### 축소·심화 기준

| 필수로 남길 것 | 시간이 남을 때만 할 것 | 이번 8시간에서 제외할 것 |
|---|---|---|
| 근거 확인, 검색/생성 진단, 평가, 관계·전역 질문 | 청크 크기 추가 비교, HyDE·Multi-Query 결과 비교, 개체 해소 사례 | 모델 로컬 설치, Python 클래스 전체 구현, Microsoft GraphRAG 신규 설치·전체 인덱싱, 자유 도메인 프로젝트 |

HyDE·Multi-Query·Small-to-Big·RAGAS는 원본 자료 위치와 결과 예시를 소개하되 필수 구현 대상으로 두지 않는다. 회차 11의 커뮤니티 탐지는 준비된 그래프의 군집 결과를 관찰한다. 회차 12는 미니 GraphRAG의 입력·중간 산출물·Local/Global 동작을 확인한다.

## 수료 판단

회차별 필수 문항 24개 통과와 종합 실습 3개 제출을 모두 확인한다. 종합 실습은 각 질문의 근거가 답변을 지지하는지, 다른 경로와 비교한 이유가 타당한지 강사 또는 조교가 확인한다. `waived` 상태는 보충 확인 전까지 미완료로 남긴다.

수업 후 남겨야 하는 것은 코드 파일의 분량이 아니라 **“이 질문에는 어떤 검색 경로가 필요하고, 결과를 어떻게 검증하는가”**를 설명할 수 있는 실습 기록이다.
